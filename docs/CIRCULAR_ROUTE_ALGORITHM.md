# Circular route generation

Implementation: `src/features/circular-routing/*` (pure) and
`src/server/services/circular-route-generator.ts` (orchestration).

## 1. Candidate generation

For a start `S` and target distance `D`:

1. A seeded PRNG (mulberry32) is created from the request, so the same request always yields the same candidates.
2. Five anchor patterns are used — `triangle`, `quadrilateral`, `asymmetric-oval`, `wide-loop`, `compact-loop` —
   selected according to the requested loop shape (compact / wide / adventure).
3. Each pattern has an anchor count, relative bearings, per-anchor radius factors and a circumference factor that
   converts the target distance into an initial radius.
4. Radial jitter (±15%) and angular jitter (±13°) are applied per candidate.
5. Clockwise or anticlockwise orientation is honoured; `automatic` picks per candidate from the seeded stream.
6. Candidates are routed as `S → A → B → S` or `S → A → B → C → S`.

24 candidates are generated by default.

## 2. Distance convergence

For each candidate the achieved length `L` is compared with `D`:

- anchor radii are multiplied by `clamp(D / L, 0.6, 1.6)`;
- the candidate is re-routed, up to two extra iterations;
- a candidate within ±10% is accepted immediately;
- otherwise the best attempt is kept, and anything beyond ±35% is rejected outright.

The UI always shows the _actual_ distance, never the requested one.

## 3. Rejection rules

A candidate is discarded when it:

- misses the target distance by more than 35%;
- includes prohibited access (>0.5% of distance);
- includes any footpath-only section while the access policy is `strict`;
- retraces more than 42% of its own distance;
- has less than 40% access-data coverage under `strict`;
- fails to return to within 250 m of the start.

## 4. Deduplication

`routeSignature()` builds both an ordered way-id set and a ~60 m spatial cell set. Overlap is the higher of the two
Jaccard similarities; candidates overlapping an already-kept route by more than 62% are dropped. Total distance is
never used as a similarity measure.

## 5. Scoring

```
score = distanceFit      × 0.24
      + accessConfidence × 0.18
      + offRoadFit       × 0.15
      + roadStressFit    × 0.12
      + climbingFit      × 0.10
      + surfaceFit       × 0.08
      + routeUniqueness  × 0.07
      + loopShapeQuality × 0.06
```

Loop-shape quality uses the isoperimetric ratio `4πA / P²`, so a circle scores ~1 and a there-and-back line scores ~0.
Every component is stored on the candidate and surfaced in the route card under “Why this option was selected”.

## 6. Choosing three alternatives

From the deduplicated, ranked list:

1. **Most off-road** — highest off-road percentage.
2. **Balanced** — highest total score of the remainder.
3. **Easier / lower risk** — best combination of confirmed access, data coverage and gentle climbing.

The UI describes these as the best match for the stated preferences, never as an objectively best route.
