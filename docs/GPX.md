# GPX export

Implementation: `src/features/gpx/generate.ts`, endpoint `POST /api/gpx/export`.

## What is exported

- GPX 1.1 with the correct namespace and schema location.
- `<metadata>`: name, description, ISO-8601 timestamp, keywords.
- `<wpt>` entries for the start, the finish and user-designated via points (shaping points are omitted deliberately —
  they shape the line, they are not places).
- One `<trk>` containing the whole route.
- One `<trkseg>` per section, so routed and hand-drawn sections stay distinguishable.
- `<ele>` per point where elevation is known; omitted rather than zero-filled where it is not.

Coordinates are written as `lat`/`lon` attributes with 7 decimal places (~1 cm), using the full-resolution geometry —
the downsampling used for the elevation chart never reaches the export.

## Escaping and filenames

All text goes through `escapeXml()`, which escapes `& < > " '`. Filenames are generated by `gpxFilename()`, which
slugifies each part, so `../../etc/passwd` becomes a harmless slug. Example:

```
trailloop-chorleywood-hertfordshire-mtb-25km.gpx
```

Response headers:

```
Content-Type: application/gpx+xml; charset=utf-8
Content-Disposition: attachment; filename="trailloop-…-25km.gpx"
```

## Demo mode

In fixture mode the description states that the file was generated from synthetic data. If the route contains
hand-drawn sections, the description also records that their access status is unverified.

## Tests

`tests/unit/gpx.test.ts` parses the generated XML with `fast-xml-parser` and asserts: valid document structure, GPX
1.1 attributes, coordinate order, closed-loop start/end equality, waypoint presence and types, elevation
serialisation (including gaps), separate segments for hybrid routes, and special-character escaping.
`tests/integration/api-routes.test.ts` covers the endpoint, its headers and its validation.
